# Deterministic MCP client

## Purpose

`cmd/client` is a deterministic MCP client used to prove the governed MCP backend can be consumed through the MCP protocol without involving an LLM.

It is not a raw business HTTP client. It uses:

```text
MCP protocol -> Streamable HTTP transport -> /mcp endpoint
```

The client calls MCP operations such as:

```text
tools/list
tools/call get_campaign_performance
tools/call get_conversion_funnel
tools/call get_tracking_health
tools/call get_data_freshness
```

## Command

With the MCP server running:

```bash
DEMO_BEARER_TOKEN=replace-me make run-client
```

Equivalent direct command:

```bash
DEMO_BEARER_TOKEN=replace-me go run ./cmd/client
```

Optional flags:

```bash
go run ./cmd/client \
  --endpoint http://localhost:8080/mcp \
  --campaign autumn-sale \
  --market UK \
  --start-date 2026-09-14 \
  --end-date 2026-09-20
```

## Flow

The deterministic client performs this sequence:

```text
1. Connect to the MCP server using the official MCP SDK client.
2. Authenticate using the configured bearer token.
3. Call tools/list.
4. Verify all required governed tools are available.
5. Call the four investigation tools in a fixed order.
6. Capture evidence IDs from structured tool results.
7. Emit a structured JSON run record.
```

Required tools:

```text
get_campaign_performance
get_conversion_funnel
get_tracking_health
get_data_freshness
```

The client verifies these are present before running the sequence. This preflight check is implemented as:

```go
verifyRequiredToolsAvailable(...)
```

It fails early if the client is pointed at the wrong MCP server or if the server's tool contract has changed.

## Output

The client writes a JSON run record to stdout.

Example shape:

```json
{
  "run_id": "client-20260921T041500Z",
  "mode": "deterministic_client",
  "campaign": "autumn-sale",
  "market": "UK",
  "start_date": "2026-09-14",
  "end_date": "2026-09-20",
  "tools_called": [
    "get_campaign_performance",
    "get_conversion_funnel",
    "get_tracking_health",
    "get_data_freshness"
  ],
  "evidence_ids": [
    "ev-campaign-uk-autumn-sale-20260914-20260920",
    "ev-funnel-uk-autumn-sale-20260914-20260920",
    "ev-tracking-incident-017",
    "ev-freshness-20260921T0415Z"
  ],
  "diagnosis": {
    "cause": "conversion_tracking_under_reporting",
    "confidence": 0.91,
    "summary": "Actual purchases are stable; Safari conversion events are under-reported.",
    "evidence_ids": [
      "ev-campaign-uk-autumn-sale-20260914-20260920",
      "ev-funnel-uk-autumn-sale-20260914-20260920",
      "ev-tracking-incident-017"
    ],
    "limitations": [
      "The result covers the requested campaign, market, and date range only."
    ]
  }
}
```

## Notes

The diagnosis is deterministic and fixed for the seeded PoC scenario. It is not generated by an LLM.

Evaluator wiring will be added separately.
